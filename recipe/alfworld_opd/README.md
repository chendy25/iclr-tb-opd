# ALFWorld Native OPD (Phase 2')

Cross-env **ALFWorld** on-policy distillation (OPD), implemented **natively in this
repo** (`iclr/verl`). No `refs/ATOD` at train time.

- **Env interaction:** verl V1 agent loop `alfworld_agent`
  (`verl/experimental/agent_loop/alfworld_agent_loop.py`) — one ALFWorld episode
  per `run`. Assistant tokens masked `1`, environment-observation tokens masked `0`.
- **Objective:** the repo's own distillation OPD, identical machinery to Phase 1'
  agentic TB-OPD arm B-A0:
  `loss_mode=k1` + `use_policy_gradient=True` + `use_task_rewards=False`
  ⇒ per-token PG advantage `= logπ_T − logπ_S` (**pure OPD**, no task reward).
- This keeps ALFWorld on the same V1 stack / TB-OPD main line, so token- and
  turn-level branching (TB-OPD / TB-OPD-Turn) can be enabled later with the same
  `distillation.tb_opd.*` knobs.

The stub parquet carries no task content — ALFWorld games are sampled from
`$ALFWORLD_DATA` (all ~6k train games are registered; `extra_info.index` seeds which
one a slot draws). So **#stub rows = games touched per epoch**, and `rollout.n`
replicas of one row play the *same* game. Native OPD uses `n=1`: the advantage is
per-token `logπ_T − logπ_S`, so there is no group to compare against; `n>1` only
matters for GRPO or TB-OPD branching.

## Relation to ATOD's ALFWorld config

Reference: `refs/ATOD/examples/sod_trainer/run_alfworld_sod_qwen3_4b.sh`. Matched:
`lr=1e-6`, `adv_estimator=grpo`, `use_kl_loss=False`, `enable_thinking=False`,
`val_kwargs.temperature=0.4 / do_sample=True`, `val_data_size=128`,
`max_prompt_length=2048`, `env.max_steps=50`. Deliberate divergences:

- **`max_response_length` (512 → 12288).** Not a discrepancy: in ATOD one training
  row is a *single turn* (history is re-injected into the prompt each step), while
  an agent-loop row is a *whole episode* transcript.
- **`rollout.n` (8 → 1).** That ATOD script is SOD (`mode=stepwise`, `opd_only=false`),
  which needs a group for its reward baseline. Pure OPD's advantage is per-token
  `logπ_T − logπ_S`, so there is nothing to compare across a group.
- **stub rows (16 → 6400).** ATOD sets `train_data_size == train_batch_size`, i.e.
  one step per epoch over a fixed 16 games, repeated for 150 epochs. We instead
  sweep the full ~6.4k-game train split; step count ends up comparable (200 vs 150).
- **No `<think>` block requested (ATOD asks for one).** We pass
  `enable_thinking=False`, and Qwen3's chat template answers that by pre-filling an
  empty `<think></think>` into *every* generation prompt (`enable_thinking is defined
  and ... is false`). The tag therefore can never appear in generated text, so both
  the prompt instruction and ATOD's `<think>` validity check are dropped — keeping the
  check pinned `alfworld_invalid_action_frac` to exactly 1.0 and masked whether
  `<action>` itself parsed. To restore real thinking, drop the `enable_thinking` kwarg
  entirely (leaving it *undefined* injects nothing) and re-budget: Qwen3 think blocks
  run to hundreds of tokens per turn, so `ALFWORLD_MAX_TURN_TOKENS` and
  `MAX_RESPONSE_LENGTH` both need to grow substantially.
- **`use_invalid_action_penalty` not ported.** It edits `token_level_scores`, which
  never reaches the advantage when `use_task_rewards=False`. The signal is still
  observable via the `alfworld_invalid_action_frac` extra field.
- **Teacher is vanilla, not GRPO'd (deliberate).** ATOD runs two stages:
  `examples/grpo_teacher_trainer/run_alfworld_grpo_qwen3_30ba3b.sh` first GRPO-trains
  the 30B-A3B on ALFWorld, and the SOD script then distils *that* checkpoint. We skip
  stage 1. Under `use_task_rewards=False` there is no task signal at all, so the
  student's ceiling is exactly the teacher's policy — expect near-floor success rate.
  That is accepted here because the goal is the *relative* TB-OPD vs plain-OPD
  comparison; read `actor/distillation/loss` and `alfworld_invalid_action_frac` as the
  discriminating metrics rather than `critic/score/mean`. Add stage 1 before making
  any absolute claim about ALFWorld competence.

## Notes / follow-ups

- **TextWorld is not thread-safe; env calls hold a process lock.** ALFWorld parses PDDL
  through a parser with non-per-instance state, and `batch_size=1` selects SyncBatchEnv,
  so the parse runs in whatever executor thread the pool used. Unsynchronized, 24
  concurrent resets in one process failed 23 times (`IndexError` / `FailedToken` /
  `TypeError` from inside `tatsu`) against zero serially. `env_pool` therefore
  serializes reset *and* step — step alone accounted for part of the failures, so
  locking game loading only is not enough. Generation is awaited outside the lock, so
  the throughput cost is minor. If ALFWorld episodes start dying en masse, check this
  first: `probe_reset_concurrency.py` reproduces it in ~2 minutes.
- **Episode failures are silently padded unless refill is on.** By default a group whose
  episode raised keeps its batch slot and materializes nothing, and the trainer pads the
  shortfall with synthetic rows copied from row 0. A run then reports full batches,
  near-perfect success, and 1–8 distinct games per 64-row batch while actually training
  on a handful of trajectories. `trainer.v1.sampler.sync_refill_failed_groups=True`
  refills instead. `alfworld_gamefile` / `alfworld_seed` in the rollout dump are the
  cheapest padding detector: they should show ~64 distinct values per 64-row batch.
- **Eval split:** `AgentLoopBase.run` receives `validate`, so validation rollouts
  play held-out games (`ALFWORLD_EVAL_SPLIT`, default `valid_unseen`) while training
  uses `ALFWORLD_TRAIN_EVAL`. Each split builds its own `AlfredTWEnv` pool, so the
  first validation step pays a one-off game-scan cost.
- **Legacy ATOD path:** `STACK=atod` (`run_native_opd.sh`, `main_sod` +
  `mode=uniform`/`opd_only=true`) is kept only as a fallback.
